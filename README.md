# Factura — тестове завдання Unity developer

Кор-механіка: автомобіль з туреллю їде вперед по рівню, гравець керує кутом стрільби
свайпом. Вороги стоять в idle, при наближенні авто біжать до нього і завдають шкоди.
Мета — проїхати рівень, знешкодивши якомога більше ворогів і не втративши все ХП.

**Unity 6000.3.9f1**, URP, портретна орієнтація, мобільні налаштування.

## Залежності

| Пакет | Навіщо |
|---|---|
| [VContainer](https://github.com/hadashiA/VContainer) | DI-контейнер, єдина точка збірки графа залежностей |
| [UniTask](https://github.com/Cysharp/UniTask) | Асинхронний цикл раунду без корутин і без алокацій |
| Input System | Ввід через `Pointer`, спільний для миші й тача |
| GUI Pro — Simple Casual (Layer Lab) | Спрайти, шрифти та префаби для HUD |

## Архітектура

Композиційний корінь — `GameLifetimeScope`. Увесь граф залежностей зібраний там і
більше ніде.

```
Assets/Game/Scripts/
  Core/        GameStateMachine, GameFlow, IResettable, ScoreService
  Events/      EventBus + типізовані події гри
  Installers/  GameLifetimeScope
  Input/       IInputService → PointerInputService
  Configs/     ScriptableObject-конфіги рівня, авто, зброї, ворога, ефектів
  Player/      CarController, TurretAim, TurretShooter, AimLine
  Combat/      IDamageable, Health, Projectile, ProjectileService
  Enemies/     EnemyAgent (FSM), EnemySpawner, EnemyAnimator, EnemyHealthBar
  Level/       GroundTiler, LevelProgress
  CameraRig/   CarFollowCamera, CameraShake
  Vfx/         VfxService
  UI/          HudView, GameResultView, UiPunch, UiFlash, UiPulse
```

### Цикл раунду

`GameFlow` реалізує `IAsyncStartable` і описує весь раунд одним читабельним методом:

```
скинути стан → чекати тап → їхати → (фініш | ХП скінчилось) → результат → чекати тап → спочатку
```

Стан живе в `GameStateMachine`; підсистеми підписані на його подію і не знають одна про
одну.

**Рестарт без перезавантаження сцени.** Кожна система зі станом реалізує `IResettable`;
`GameFlow` скидає їх групою, тому нова система підхоплюється рестартом самим фактом
реєстрації в контейнері.

### Рішення, які варто пояснити

- **Кулі на свіп-рейкасті, а не на колайдерах.** На 70 м/с куля за кадр пролітає більше,
  ніж ширина тіла, і колайдерна куля проскакувала б крізь ціль між фізичними кадрами.
- **Без NavMesh.** Земля пласка, погоня — пряма лінія. Ручний steering коштує кілька
  рядків там, де NavMesh коштував би запікання, компонент агента й тюнінг без виграшу.
- **FSM ворога на enum, а не клас-на-стан.** Для чотирьох станів клас-на-стан — це
  церемонія; вісь розширення тут «новий тип ворога / нова зброя», і її закривають
  `IDamageable`, `Health` і конфіги.
- **Шина подій введена не наперед.** `EventBus` з'явився в той момент, коли в однієї
  події стало кілька незалежних реакцій: смерть ворога слухають і лічильник очок, і
  партікли. Завдяки цьому `EnemySpawner` не знає, що в грі взагалі є підрахунок очок.
  Локальні події (`EnemyAgent.Killed`, `Projectile.Hit`) навмисно лишились локальними:
  компоненту всередині префаба потрібна подія свого об'єкта, а не будь-яка подія рівня.
- **Пули на `UnityEngine.Pool.ObjectPool`** для куль і ворогів, з прогрівом на старті:
  нуль алокацій під час стрільби і жодного хітчу на першій черзі.
- **Тайлінг землі міряє довжину тайла з рендерерів моделі**, а не бере число з
  інспектора, тож заміна чи перемасштабування моделі нічого не ламає.
- **Момент шкоди приходить з анімації.** Агент лише починає замах; `EnemyAnimator`
  викликає `DeliverAttack()` на кадрі влучання, дивлячись на нормалізований час стану —
  тож зміна швидкості анімації не розсинхронізує удар. У цей момент дистанція
  перевіряється ще раз: якщо авто встигло від'їхати, удар промахується.

## Асети

Ріг і анімації стікмена (idle, run, attack, death) — з Mixamo, імпортовані як Humanoid,
root motion забейканий у позу, бо рух задає код.

Модель кулі, партікли, трейли й матеріали — довільні, зроблені в проєкті.
